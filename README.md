# Kōtuku Web Site

Source for the official Kōtuku website at [https://kotuku.dev](https://kotuku.dev)

The site is entirely static.  Everything that gets published lives in [site/](site/), which is served verbatim by
GitHub Pages.  Most of the documentation pages in that folder are *generated* from sources held in the
[Kōtuku SDK](https://github.com/kotuku-group/kotuku) repository, so they should not be edited by hand.

## Repository Layout

| Path | Purpose |
|------|---------|
| [site/](site/) | The published website; this folder is the GitHub Pages artifact |
| [build/](build/) | Generator scripts, XSLT stylesheets and the wiki page template |
| [build/nav.xsl](build/nav.xsl) | Shared navbar and sidebar; the single source for site navigation |
| [build/gen-nav.sh](build/gen-nav.sh) | Regenerates the wiki header and the API index from their templates and `nav.xsl` |
| [.github/workflows/static.yml](.github/workflows/static.yml) | Deployment workflow |

### Published Content (`site/`)

- **`index.html`**, **`gallery.html`** — hand-written landing and showcase pages
- **`modules/api.html`** — API index, generated by `build/gen-nav.sh` from `build/api.template.html`
- **`modules/*.html`** — module reference, generated from the SDK's `docs/xml/modules/` files
- **`modules/classes/*.html`** — class reference, generated from `docs/xml/modules/classes/`
- **`wiki/*.html`** — rendered copies of the SDK's `docs/wiki/` Markdown pages
- **`gallery/`** — screenshots and SVG demonstrations
- **`css/`**, **`js/`**, **`images/`**, **`favicon.ico`** — Bootstrap 5 based assets shared by every page
- **`CNAME`** — custom domain record for GitHub Pages (`kotuku.dev`)

## Site Navigation

The navbar and sidebar are defined once, in [build/nav.xsl](build/nav.xsl).  Adding a module, class or wiki page to
the navigation means editing that file and nothing else.

[build/module.xsl](build/module.xsl) and [build/class.xsl](build/class.xsl) pull the navigation in with
`xsl:import`, each overriding the `root` parameter to say how far the generated page sits below the site root.
Two pages are not produced by XSLT and so cannot import it: the wiki header, which pandoc wraps every wiki page in,
and the hand-written API index.  For those, [build/gen-nav.sh](build/gen-nav.sh) renders the navigation to a
fragment and substitutes it into a template:

| Template | Generated page |
|----------|----------------|
| [build/wiki-header.template.html](build/wiki-header.template.html) | `build/wiki-header.html` |
| [build/api.template.html](build/api.template.html) | `site/modules/api.html` |

```bash
build/gen-nav.sh          # requires xsltproc
```

Run that after editing `nav.xsl` or either template, and commit the regenerated pages.  Do not edit the generated
pages by hand; each carries a banner saying as much.  Note that the module and class lists in the *body* of the API
index are maintained by hand in `api.template.html`, and need refreshing when the SDK gains or loses a module or
class.

The sidebar entry matching the current page is highlighted by `highlightNavLink()` in
[site/js/base.js](site/js/base.js), which matches on the anchor's resolved path rather than its raw `href`, so it
works at any directory depth.

## Building the Documentation

Both generators are Tiri scripts (see [wiki/Tiri-Reference-Manual.html](site/wiki/Tiri-Reference-Manual.html)) executed by the Kōtuku `origo` interpreter.  Each one locates the SDK by searching upwards for `CMakeLists.txt` (or accepts an explicit `sdk` path), builds a shell script of conversion commands, runs it, then deletes it.  Windows is not supported for either script.

### Module and Class Reference

```bash
origo build/docgen.tiri sdk=/path/to/kotuku
```

Requires `xsltproc` on the system path.  Every `.xml` file under `<sdk>/docs/xml/modules/` is transformed into a
matching `.html` file under `site/modules/`, preserving the sub-folder structure.  The stylesheet is selected by the `xml-stylesheet` instruction inside each XML document and resolved against [build/](build/), which is why
[build/module.xsl](build/module.xsl) and [build/class.xsl](build/class.xsl) must sit alongside the script.

Options:

- `sdk=<path>` — path to the Kōtuku SDK; searched for if omitted
- `output=<file>` — where to write the generated shell script (default `temp:docgen.sh`)
- `dry-run` — generate the shell script but do not run it

### Wiki Pages

```bash
origo build/docgen_wiki.tiri sdk=/path/to/kotuku
```

Requires `pandoc` on the system path.  Markdown files in `<sdk>/docs/wiki/` are converted to HTML5 with GitHub-flavoured Markdown rules, then wrapped in [build/wiki-header.html](build/wiki-header.html) and [build/wiki-footer.html](build/wiki-footer.html), with the page title derived from the file name and `.md` links rewritten to `.html`.  Output is written to `site/wiki/`.

Options:

- `sdk=<path>` — path to the Kōtuku SDK; searched for if omitted
- `pandoc=<file>` — explicit path to the pandoc executable
- `wiki=<folder>` — source Markdown folder (default `sdk:docs/wiki/`)
- `output=<file>` — where to write the generated shell script
- `dry-run` — generate the shell script but do not run it
- `--help` — print usage

## Deployment

[.github/workflows/static.yml](.github/workflows/static.yml) publishes [site/](site/) to GitHub Pages on every push
to `main`, and can also be triggered manually from the Actions tab.  There is no build step in CI — regenerate the
documentation locally and commit the resulting HTML.
